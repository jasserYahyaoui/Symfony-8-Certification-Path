# ADR-0003 — Docusaurus as the presentation layer

- **Status:** Accepted
- **Date:** 2026-08-31
- **Deciders:** Project owner
- **Amends:** [ADR-0001](0001-build-time-php-static-runtime.md) — its presentation layer only

## Context

ADR-0001 settled the deployment model: PHP owns everything at build time, the
deployed artefact is static, GitHub Pages serves it. That decision stands.

What ADR-0001 did *not* settle well was the presentation. Its first
implementation was a hand-rolled generator producing three flat HTML pages.
That is adequate for a proof of pipeline and inadequate for the actual product:
this repository will hold a course spanning fifteen official topics and
hundreds of atomic items. Such content needs sidebar navigation, search,
breadcrumbs, previous/next links, anchored headings, code highlighting, dark
mode and a mobile layout — and every one of those, hand-written, is a
maintenance cost that buys nothing unique to this project.

The owner asked for the presentation of a documentation site.

## Decision

**Docusaurus 3.10 renders the site, in `website/`.** PHP keeps everything else.

```text
docs/syllabus/*.yml, content/questions/*.yml      canonical data (§11)
        │
        ▼  php bin/cert validate  ·  coverage  ·  build
website/docs/**.md          generated course, coverage and exclusion pages
website/static/data/*.json  generated Practice and Exam payloads
        │
        ▼  npm --prefix website run build
website/build/              static site  ──►  GitHub Pages
```

- `website/docs/` and `website/static/data/` are **generated and gitignored**.
  The YAML remains the single source of truth (§11); nothing is hand-edited in
  two places.
- Practice and Exam are React pages under `website/src/pages/`, consuming the
  generated payloads.
- The sidebar is autogenerated from the directory tree the PHP generator
  writes, so adding an official item to the matrix adds its page and its
  navigation entry with no second file to update.

## Rationale

- **ADR-0001 is unchanged in substance.** PHP still owns the canonical data,
  the schema validation, the §12 rule set and the coverage engine; the artefact
  is still static; there is still no server, no account and no secret in client
  code (§13). Only the renderer changed.
- **Holdout isolation stays structural.** `PayloadBuilder` still assembles the
  Practice payload from the learning pool alone and still asserts no leak, so a
  holdout question is absent from the file the Practice page can fetch. Moving
  to React changed nothing about that guarantee, and the CI and production
  smoke test both re-check the shipped payload's declared pool.
- **`onBrokenLinks: 'throw'`** makes Docusaurus the site-level counterpart of
  CI rule `LNK-001`: a dead link fails the build instead of shipping.
- Docusaurus gives versioned docs and i18n for free. Both are plausibly needed
  later — a future Symfony version, and the §5 requirement to migrate learners
  toward English wording.

## Consequences

**Positive**

- Course content is authored as Markdown, which is what a course is.
- Navigation, search and responsive layout come from a maintained theme rather
  than from bespoke CSS this project would have to own.
- The learner-facing site now reads as documentation, which is the shape of the
  product.

**Negative, and accepted**

- A Node toolchain joins the PHP one. CI grows a `npm ci` and a site build; the
  gate is slower.
- 1270 npm packages are now part of the build surface. They affect the build
  only — nothing is executed at request time, and the deployed artefact stays
  static.
- The generated tree must exist before `npm run build` can run, so a fresh
  clone needs `php bin/cert build` first. CI enforces that order explicitly.

**Known limitation**

- `twig` cannot be added to Prism's `additionalLanguages`: its templating
  languages assume a global `Prism` that the Docusaurus 3.10 SSR bundle does
  not provide, and adding it fails the build with `Prism is not defined`.
  `php`, `yaml` and `bash` work and are enabled. Twig samples in Lot 6 should
  be fenced as `html` until this is resolved upstream. This is recorded rather
  than worked around silently, because a future contributor will otherwise
  re-attempt it and lose the same time.
