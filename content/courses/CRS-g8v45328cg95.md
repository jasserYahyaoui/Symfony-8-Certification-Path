## Objectif

Atteindre depuis un test les objets du framework — le conteneur, un service, le
noyau — et comprendre pourquoi le conteneur de test n'est pas celui de
production.

## Prérequis

Les tests d'intégration, et les services publics et privés.

## Démarrer le noyau

```php
class NewsletterGeneratorTest extends KernelTestCase
{
    public function testSomething(): void
    {
        self::bootKernel();
        $container = static::getContainer();

        $generator = $container->get(NewsletterGenerator::class);
    }
}
```

`KernelTestCase` **redémarre le noyau à chaque test**, ce qui garantit leur
indépendance. Le noyau à démarrer est désigné par la variable d'environnement
`KERNEL_CLASS`, posée dans `.env.test` :

```env
KERNEL_CLASS=App\Kernel
```

Pour un cas plus complexe, `getKernelClass()` ou `createKernel()` peuvent être
redéfinies, et l'emportent alors sur la variable.

`bootKernel()` accepte des options :

```php
self::bootKernel(['environment' => 'my_test_env', 'debug' => false]);
```

`debug` à `false` est recommandé en intégration continue : le cache n'est plus
vidé, et les tests s'en trouvent nettement plus rapides.

## Le conteneur de test

`static::getContainer()` ne rend pas le conteneur ordinaire mais un **conteneur
de test spécial**. Sa particularité est décisive : il donne accès aux services
publics **et aux services privés non supprimés**.

En production, un service privé n'est pas récupérable par `get()`. Le conteneur
de test lève cette restriction, sans quoi la plupart des services d'une
application — privés par défaut — seraient intestables.

La limite : un service privé **supprimé**, parce qu'aucun autre ne l'utilise,
reste inaccessible. Il faut alors le déclarer public dans
`config/services_test.yaml`.

## Remplacer un service par une doublure

Le même conteneur permet de **remplacer** un service avant de l'utiliser :

```php
$repository = $this->createMock(NewsRepositoryInterface::class);
$repository->expects(self::once())
    ->method('findNewsFromLastMonth')
    ->willReturn([new News('…')]);

$container->set(NewsRepositoryInterface::class, $repository);

// reçoit la doublure
$generator = $container->get(NewsletterGenerator::class);
```

Aucune configuration supplémentaire n'est requise : `set()` fonctionne sur ce
conteneur, y compris sur un **alias privé**. L'ordre compte — poser la doublure
**avant** de demander le service qui en dépend.

## Depuis un test d'application

Le client expose les mêmes objets :

```php
$client->getContainer();
$client->getKernel();
```

## Pièges d'examen

**`static::getContainer()` rend un conteneur de test**, pas le conteneur de
production : les services privés y sont accessibles.

**Un service privé supprimé reste inaccessible** — il faut le rendre public dans
`config/services_test.yaml`.

**`container->set()` doit précéder `get()`** du service consommateur.

**`KERNEL_CLASS` désigne le noyau** ; `getKernelClass()` l'emporte sur elle.

**Le noyau redémarre à chaque test**, pas une fois par classe.

## Points clés

- `bootKernel()` puis `static::getContainer()`.
- Le conteneur de test expose les services privés non supprimés.
- `set()` remplace un service, alias privé compris, avant sa consommation.
- `KERNEL_CLASS` dans `.env.test` ; `debug: false` accélère la CI.
